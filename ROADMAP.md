# Дорожная карта: от MVP к продукту, который можно продавать

## Контекст

Сейчас есть два рабочих контура: **продажи** (`main.py` + `outreach.py` — лиды из 2GIS,
открывашки, аудиты) и **продукт** (`app.py` — локальная панель: мониторинг отзывов 2GIS →
Telegram, маршрутизация по чатам, бот-админка). Это честный MVP: работает, но живёт на
домашнем ПК, выглядит утилитарно, и из «ценности за деньги каждый месяц» в нём только
алерты. Цель плана — довести визуал, функционал и организацию до уровня, на котором
продукт не стыдно показывать на встрече, он работает без твоего ноутбука и удерживает
клиента после первого месяца. Реализация — отдельными этапами после утверждения.

---

## 1. Бенчмарк: как это устроено у компаний, которые этим живут

**Глобальные:** Birdeye, Podium, NiceJob, Grade.us, ReviewTrackers, Reputation.com.
**СНГ:** RocketData (лидер: карточки+отзывы всех геосервисов), Repometr, Точка.Отзывы,
Brand Analytics (enterprise-тональность), Aplaut. **Казахстан:** специализированных
игроков почти нет — обычно SMM-агентства руками. Это и есть ниша.

Стандартный набор такого продукта (что из этого у нас уже есть → ✅):

| Блок | Что делают все | У нас |
|---|---|---|
| Мониторинг | все площадки в одном кабинете, алерты в день публикации | ✅ 2GIS → Telegram |
| Ответы | ответ из кабинета (где есть API) + **AI-генерация в тоне бренда** | ⚠️ статичный шаблон |
| Сбор отзывов | SMS/WhatsApp/QR-кампании, недовольных — в приватную форму | ❌ (ядро по PLAN.md!) |
| Аналитика | динамика рейтинга, доля отвеченных, темы жалоб, конкуренты | ❌ только текущий срез |
| Отчётность | брендированный PDF/email-отчёт клиенту — главный инструмент удержания | ⚠️ только разовый аудит |
| Мультилокации | сети, роли, white-label для агентств | ❌ |
| Продажи | бесплатный «скан/аудит» как лид-магнит, демо-кабинет с данными | ✅ аудит / ❌ демо |

Организационные выводы из их модели:
- **Продаёт не мониторинг, а отчёт и рост рейтинга.** Birdeye/Podium показывают на демо
  график «было 3.9 → стало 4.6» и брендированный отчёт. Алерты — гигиена, не ценность.
- **Вход — бесплатный аудит** (у нас уже есть генератор — это сильная карта).
- **Удержание — еженедельный/ежемесячный автоматический отчёт**: клиент видит, за что платит.
- **Канал масштабирования — white-label для агентств**, не прямые продажи в одиночку.
- Чего у них **нет** и нам не надо: своя LLM, мобильное приложение, автопостинг туда,
  где нет API (в 2GIS его нет — наша модель «черновик → владелец публикует» легальна и достаточна).

## 2. Этапы (в порядке движения)

### Этап 1 — «Витрина»: визуал и материалы для продаж
*Цель: через 2–3 недели не стыдно открыть панель на встрече и оставить клиенту PDF.*

1. **Бренд и редизайн панели** (`app.py`, вынести CSS/шаблоны в `templates/`):
   - имя продукта + логотип (выбрать: например «KartaRep», «Otzyvo», «ReiKZ» — решение за тобой),
     favicon, единая палитра, нормальная типографика;
   - список компаний: карточки вместо таблицы — рейтинг крупно, мини-спарклайн динамики,
     светофор «здоровье карточки» (зелёный/жёлтый/красный по правилам из `lead_scoring.py`);
   - тёмная тема не нужна; нужна аккуратная светлая, как у RocketData/Birdeye.
2. **История и графики** (новая таблица `rating_history` в `db.py`: снапшот
   рейтинг/кол-во/без-ответа при каждой проверке):
   - страница компании: график рейтинга и числа отзывов по неделям (SVG без JS-библиотек
     или лёгкий Chart.js), распределение оценок 1–5, % отвеченных;
   - это же — данные для отчётов (п. 4) и демо.
3. **Демо-режим** (`python app.py --demo` или сид-скрипт): фейковая компания с 6 месяцами
   истории, парой «свежих» негативов и красивыми графиками — показывать на встрече без
   ожидания парсинга и без чужих данных.
4. **Ежемесячный отчёт клиенту** (переиспользовать рендер из `outreach.py`):
   страница `/company/{id}/report?month=...` → печать в PDF: рейтинг был→стал, новые
   отзывы, закрытый негатив, динамика vs прошлый месяц, логотип клиента. Кнопка
   «Отправить в Telegram клиента».
5. **Аудит 2.0** (продажный документ): объединить outreach-аудит с живыми данными —
   сравнение с 2–3 конкурентами (выбираются вручную или из прогона `main.py`), брендинг,
   QR на твой WhatsApp в подвале.
6. **Продажная упаковка (не код):** сценарий 15-минутного демо (аудит → добавляем карточку
   клиента вживую → через минуту его реальный негатив без ответа → «это будет прилетать
   вам в Telegram в день публикации» → отчёт), шаблон КП с тарифами из PLAN.md §3.3,
   шаблон кейса «3.9 → 4.5 за 2 месяца».

### Этап 2 — Надёжность: работает без твоего ноутбука
*Цель: можно обещать клиенту «узнаете о негативе в тот же день» и не врать.*

1. **VPS-деплой**: дешёвый VPS (4–8 GB под Playwright), systemd-сервис или Docker,
   Caddy с HTTPS, домен. Чек-лист деплоя в README.
2. **Авторизация панели** (обязательно до выхода в интернет): простой логин/пароль
   (session cookie), один пользователь-владелец. Сейчас панель открыта всем — в
   интернет в таком виде нельзя.
3. **Здоровье парсера** (риск №1 по PLAN.md): страница «Состояние» — последние проверки,
   ошибки подряд; алерт админу в Telegram, если N проверок подряд падают («парсер умер —
   чинить селекторы»); ретраи с экспонентой уже частично есть, добавить общий счётчик.
4. **Очередь проверок под масштаб**: при 20+ компаниях разносить проверки по времени
   (jitter, лимит проверок/час), чтобы не словить бан 2GIS; готовность к прокси —
   опционально, только когда упрёмся.
5. **Бэкап**: ежедневная копия `monitor.db` (cron + копия в облако), экспорт/импорт.

### Этап 3 — Ценность: за что платят каждый месяц
*Цель: удержание >70% на 2–3 месяце (метрика из PLAN.md §5).*

1. **AI-черновики ответов** (LLM API, копейки за отзыв): на каждый новый отзыв — 2
   варианта ответа в тоне бренда (пресет тона в карточке компании: «тёплый/деловой/...»,
   few-shot из реальных ответов клиента). В Telegram-алерте вместо статичного шаблона.
   Это сегодня стандарт рынка — без него продукт выглядит устаревшим.
2. **Воронка сбора отзывов — ЯДРО** (PLAN.md называет это главной фичей, ROI понятнее всего):
   - публичная страница `/r/{slug}` («Как вам у нас?»): 4–5★ → кнопка «Оставить отзыв в 2ГИС»
     (ссылка на карточку), 1–3★ → приватная форма → жалоба летит владельцу в Telegram
     (негатив перехвачен до публикации — легально: зовём всех, недовольных сначала слушаем);
   - QR-генератор (на стойку/чек) + шаблоны сообщений клиентам (WhatsApp);
   - метрика в отчёте: «переходов → отзывов получено». Требует VPS (этап 2).
3. **Еженедельный TG-дайджест клиенту**: рейтинг, новые отзывы за неделю, динамика —
   автоматическое напоминание «за что я плачу».
4. **Тональность и темы жалоб** (LLM-классификация: сервис/цена/персонал/чистота...) —
   в отчёт и на страницу компании. Дёшево, выглядит дорого.

### Этап 4 — Масштаб и организация
*Цель: больше компаний на тебя одного + канал через агентства.*

1. **Google Business Profile** (официальный API, OAuth владельца): чтение отзывов +
   **публикация ответов** — единственная площадка с легальным автоответом; продавать
   как апсейл-тариф (PLAN.md §1). Потом Яндекс (парсинг).
2. **Кабинет клиента**: read-only доступ по ссылке-токену на свою компанию (отзывы,
   графики, отчёты) — снижает поток вопросов «а что там у нас».
3. **White-label / роли** для SMM-агентств: их логотип, их клиенты, твоя инфраструктура,
   20–30% реферал (канал №3 из PLAN.md §3.4).
4. **Биллинг-лайт**: учёт тарифа/оплат/срока в панели + напоминание о продлении в твой
   админ-чат. Полноценный биллинг не строить (PLAN.md §4.2).
5. **Лендинг**: одностраничник с кейсами и формой «бесплатный аудит» — форма дёргает
   уже существующий генератор аудита.

## 3. Чего сознательно НЕ делаем (анти-скоуп)

- Автопубликация ответов в 2GIS/Яндекс — API нет, автоматизация кабинета = бан и хрупкость.
- Мобильное приложение — Telegram уже решает.
- Своя LLM / файнтюн, микросервисы, k8s — ты один, SQLite + один процесс тянут до ~100 компаний.
- Накрутка и «фильтрация» отзывов — репутационная смерть (PLAN.md §1, юр-мины).
- Полноценный биллинг/самообслуживание до 10+ клиентов.

## 4. Рекомендуемый порядок

**Этап 1 целиком + Этап 2.1–2.3** — это «можно продавать» (~3–4 недели вечерами).
Затем **3.1 и 3.2** сразу после первых 2–3 клиентов (это удержание), 3.3–3.4 следом.
Этап 4 — по факту роста: Google-API когда попросят клиники, white-label когда появится
первое агентство. Параллельно с разработкой — продажи по воронке PLAN.md §3.4 (аудиты
уже генерируются, ждать ничего не нужно).

## 5. Верификация по этапам

- **Этап 1**: демо-режим открывается за 10 секунд, отчёт печатается в PDF без верстки
  «вразнос», скриншоты панели годятся в КП; самотесты модулей зелёные.
- **Этап 2**: панель доступна по HTTPS с логином; убить процесс на VPS → systemd поднял;
  выключить твой ПК → алерты продолжают приходить; сломать селектор → админ-алерт пришёл.
- **Этап 3**: тестовый «плохой» отзыв через /r/{slug} прилетел владельцу и НЕ попал в 2GIS;
  AI-черновик отвечает в заданном тоне; дайджест приходит по расписанию.
- **Этап 4**: ответ в Google опубликован через API на тестовой карточке; кабинет клиента
  не даёт доступ к чужим компаниям.

## 6. Что переиспользуем (уже написано)

- `db.py` — миграции уже есть (`_migrate`), новые таблицы по тому же паттерну.
- `bot.py` — команды бота расширяются под дайджесты/AI-черновики.
- `lead_scoring.py` — правила «светофора здоровья» карточки.
- PLAN.md §3.3 — тарифы для КП; §3.4 — каналы продаж.
